## Findings and implementation order

There are 38 business capabilities in the running API (excluding `/health`).
25 are available through the current UI, 3 are partial, 8 lack a user interface,
and 2 are correctly blocked by server configuration/safety policy. The missing
admin authoring controls and profile Google-linking are the highest-impact gaps.
The guest catalogue may show only `guest_allowed` entries, but attempts are
authenticated by design; consequently no guest test execution can be claimed
until the backend changes its attempt authorization policy.

The matrix deliberately records endpoint-level gaps rather than hiding them
behind look-alike components. It should be updated only after browser scenarios
exercise the corresponding endpoint successfully.
